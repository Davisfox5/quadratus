## Verification against the acceptance criteria

- **Denies missing records** — `record is not None` short-circuits first, so a `RECORDS.get()` miss returns False before any subscript. Correct, and fails closed.
- **Denies absent tenants** — `bool(tenant)` rejects `""` and `None`. Redundant in practice (`auth.current_tenant` raises 401 before returning an empty value), but the criterion asked for it and it hardens other callers.
- **Denies ownership mismatch** — `record["tenant_id"] == tenant` against `catalog.RECORDS`, which carries `tenant_id` on every row (`catalog.py:4-5`).
- **Identical 404 for both cases** — missing and other-tenant records take the same branch with the same body. No enumeration oracle: `alpha` asking for `beta-1` and for `nonexistent` are indistinguishable.
- **Record(id,title) preserved** — `app.py:28` constructs only `id` and `title`; `response_model=Record` would strip `tenant_id` even if it leaked. No leak.
- **No header/query spoofing** — `tenant: str = Depends(current_tenant)` is a dependency, not a query parameter. FastAPI will not bind `?tenant=beta` to it. `auth.py` reads only the `Authorization` header and maps through `TOKENS`. There is no second path to a record: `/caption` and `/records/{id}` are the only routes.
- **401 preserved** — the dependency resolves before the handler, so an unauthenticated request to any record id still raises 401 rather than reaching the 404 guard. Untouched.
- **Task 1 preserved** — `presentation.py:3,7` still delegates to `catalog.compact_caption` rather than reimplementing it; `/caption` is unchanged.
- **Scope and size** — only `app.py` and `access.py` carry the change; `auth.py`, `catalog.py`, `presentation.py`, `README.md` are consistent with their stated read-only role. Roughly 8 changed lines, matching the estimate. No entitlement logic anywhere.
