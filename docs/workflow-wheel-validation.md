# Installed workflow wheel validation

This check builds a wheel from a temporary source copy, installs it in a separate directory, removes that build copy, and runs the installed package from another working directory. It uses only local dependencies and makes no vendor calls.

Run `tools/verify_workflow_wheel.py` with `--builder-python` pointing to a Python that has setuptools and wheel, and `--runner-python` pointing to a Python that has pytest and Quadratus runtime dependencies. The builder uses `pip wheel --no-deps --no-build-isolation --no-index`; the installation uses `pip install --no-deps --no-index --target`. The test wrapper can run with `QUADRATUS_WHEEL_BUILDER` set to the builder interpreter.

The installed probe checks that `quadratus` and its private pytest report producer load from the installation directory. It runs three real declared pytest checks: a test-body assertion must be attributable to product work, while a runtime error in a test and a setup error must be handed off as unattributable. A project-local module with the producer's familiar name is present; loading it would raise, so a successful report confirms the harness-owned producer was used. The installed package's dependencies and pytest are supplied by the runner environment. This validates wheel layout and the structured producer boundary, not a live task or full workflow acceptance.
